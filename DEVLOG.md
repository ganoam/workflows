# Devlog

Chronology of work on this repository.

## Repo setup and agent docs consolidation (Nov 18)

- Repository created as the shared home for reusable workflow documentation, consumed as `deps/workflows` in consumer repos.
- `agents/rules.md`, `agents/workflow.md`, and `recipes/` distilled from a multi-week `hw-commons` session that mixed two kinds of work: OpenTitan-style UVM-on-Verilator bring-up and upstream bug triage, and design of the public/private git publishing workflow (`.gitprivate`, hooks, `publish.sh`).
- `agents/rules.md` reviewed and confirmed binding by the owner; it now carries the generic constraints (no repo-state changes, no external actions, discussion is not instruction, style and attribution rules).
- `agents/workflow.md` extended with operating sections: doc layering, deps/submodule propagation, generated regions, debugging methodology, workaround convention, upstream reports, review loop, session lifecycle, commit style.
  Owner-reviewed and in effect.
- `recipes/` seeded and owner-reviewed: `git-privacy.md` (moved from the scripts repo), `deps-management`, `upstream-bugs`, `vendoring`.
  `dv-library-extraction` and `uvm-on-verilator` relocated to `hw-commons/recipes/` as project-local recipes; `figure-pipeline` dropped.
- README attribution/import-history work in `hw-commons` informed `vendoring.md`: three import modes (filtered merge, submodule, plain copy) with the editing discipline scoped to copyright-level "Modifications by" marking on merged code.
- `tricks/` migration from `workspaceconfig` handled manually by the owner.

## Plugin packaging and consistency model (Nov 19)

- Repo packaged as a Devin plugin: `.devin-plugin/plugin.json` manifest, injected plugin-root `AGENTS.md`, `skills/` wrappers (one per recipe) generated by the `generate-skills` skill.
- Consistency model settled: the consumer repo's `deps/workflows` pin is canonical content; plugin files are the fallback when the submodule is absent.
  Wrappers and the injected `AGENTS.md` point at `deps/workflows/` first.
  Onboarding procedure (`agent-setup`) includes a plugin-vs-pin drift check.
- Injected `AGENTS.md` instructs re-reading `rules.md`/`workflow.md` each task, so checkout edits take effect mid-session; adds standing duties (README always accurate, DEVLOG on every task, propose new recipes/tricks).
- `agents/template.md` added for consumer `AGENTS.md` files and applied to `hw-commons` (first consumer).
- `rules.md` gained the edit-approval rule: every file edit is presented verbatim via the tool's inline diff; one approval per edit, conversation beforehand is expected.
- `MAINTAINING.md` documents structure, binding hierarchy, and the common maintenance operations.

## DEVLOG entry format recipe (Nov 19)

- `recipes/devlog.md` added: house format for consumer `DEVLOG.md` files (dated sections, terse per-packet bullets recording intent and outcome; hashes and transcripts stay in `git log`).
  Trigger: `workspaceconfig`'s prose-dense entries were judged too detailed.
- Pointers added in `workflow.md`, injected `AGENTS.md`, `README`, `ROADMAP`; `skills/devlog/` wrapper added.
- `rules.md` gained a style bullet: one sentence per line in prose docs (replacing fixed-column wrapping), with prompt-the-user-on-touch as the migration mechanism for legacy content (the earlier calm-sweep-suggestion idea was dropped).
  Trigger: consumer-repo docs are hard-wrapped and painful to diff.
  Sweep of this repo's own docs queued in the roadmap.
- `MdStyle.md` added: human-facing style guide for prose docs (sentence-per-line rationale, no-em-dashes, terse-over-tutorial, generated-region exemption) in the lowRISC guide's shape.
  Owner dropped the proposed-rule candidates as document-specific; the remaining rules were made binding for agents via a `rules.md` pointer bullet, and the prompt-before-fixing-legacy-content protocol was moved into the guide generalized to all its rules.
- `recipes/snippet.md` added: end-of-day digest that scans today's DEVLOG entries across `~/code` repos and their `deps/` checkouts into `~/code/notes/snippets.md`, devlog style.
  Wrapper generated.

## Prose style sweep (Nov 19)

- `MdStyle.md` rules applied across all prose docs in the repo: hard-wrapped paragraphs and bullets unwrapped to one sentence per line, second sentences moved to indented continuation lines, em/en-dashes and `--` surrogates replaced with commas, colons, periods, or parentheses.
- `skills/generate-skills/SKILL.md` wrapper template fixed; the 8 generated `skills/*/SKILL.md` wrappers regenerated from it (agent-setup's description also picked up the recipe's real first sentence).
- ROADMAP Phase 4: em-dash consistency and sentence-per-line sweep items checked off.
- Content bugs spotted in `tricks/git-tricks.md` left in place pending owner decision: `## Spase git checkout` typo, unclosed paren under "Adding submodules", a shell comment missing `#` in the submodule-removal block, a 4-backtick fence after the `pip install` block, odd spacing in the filter-repo step-3 line.

## agent-setup: dependency-repo onboarding (Nov 20)

- `recipes/agent-setup.md` extended with a "Dependency repo" variant: a repo that only ever lives as a `deps/` checkout (e.g. `deps/scripts`) skips the submodule step and points its `AGENTS.md` preamble at the sibling `../workflows`, falling back to `~/workspaceconfig/deps/workflows` then the injected plugin copies.
  Trigger: `scripts` is a helper repo never checked out in isolation, so it carries no own workflows pin but should still follow the workflow.

## agent-setup skill registration fix (Nov 20)

- Fixed `agent-setup` never appearing in the skill list: its generated wrapper's `description` held the recipe's first sentence as a plain YAML scalar containing `: `, so the frontmatter failed to parse.
  Added a YAML-quoting rule to the `generate-skills` template (plain scalar when safe, otherwise double-quoted with `"` and `\` escaped) and re-emitted the wrapper; all 9 wrappers now parse.

## rules.md: edit diffs over full-file writes (Nov 20)

- `agents/rules.md` gained a bullet under "Editing and style": an existing file is changed through an edit with an inline diff, never through a full-file write presented for approval, so the reviewer sees what changed rather than only the new content.
  An intentional complete rewrite requires saying so explicitly and getting approval for the overwrite itself.
  Trigger: agents repeatedly presented whole-file writes whose diffs hid what the overwrite destroyed.

## agent-setup: stand-alone repo variant (Nov 20)

- `recipes/agent-setup.md` extended with a third repo type: the stand-alone non-project repo, which builds nothing and has no dependencies, hence no `deps/workflows` pin.
  Its `AGENTS.md` preamble points at the machine checkout `~/workspaceconfig/deps/workflows`; if that checkout is absent at setup time, the agent does nothing and alerts the user rather than producing a partial setup.
